## Problem Statement

The VRNB clean-up app currently shows zone-specific overview maps at `/tours/[zoneId]/[type]` (e.g., `/tours/bruz-sud/V` for bike tours in Bruz Sud). Each zone map displays only the Parcours belonging to that single zone and practice type. Users (volunteers and organizers) want a global view showing **all Parcours from all zones and both practice types (bike and walking) on a single map**, along with a downloadable PDF of this global map. This global map should use the same color assignment as the zone maps: each tour keeps its zone-local index color (so V1 and V200 both get the first color, V2 and V201 both get the second color, etc.), meaning colors will repeat across zones — this is expected and desired for visual consistency with zone maps.

## Solution

Add a new route `/tours` that displays a global overview map with all Parcours from all zones and both practice types. The map reuses the existing Leaflet infrastructure and the same `TOUR_COLORS` palette. Add a new global PDF (`Carte_tous_les_parcours.pdf`) generated by the existing `generate-pdfs.ts` pipeline, integrated into the incremental generation system so it auto-regenerates when any tour changes (trace, segments, Fiche) or when a new zone is added.

## User Stories

1. As a volunteer, I want to see all Parcours from all zones on one map at `/tours`, so that I can get an overview of the entire Bruz territory coverage.
2. As a volunteer, I want each Parcours on the global map to have the same color it has on its zone map, so that I can visually correlate between the global and zone-specific views.
3. As a volunteer, I want to see both bike (V) and walking (P) tours together on the global map, so that I have a complete picture in one place.
4. As a volunteer, I want start/end markers and labels on the global map like on zone maps, so that I can identify each Parcours.
5. As a volunteer, I want the global map to fit all tours in view automatically, so that I don't need to pan/zoom to see everything.
6. As an organizer, I want a downloadable PDF of the global map (`Carte_tous_les_parcours.pdf`), so that I can print it for planning or communication.
7. As an organizer, I want the global PDF to use the same visual style (colors, markers, labels, legend) as the zone PDFs, so that documents are consistent.
8. As a referent running the generation pipeline, I want the global PDF to be part of the incremental pipeline (`generate:pdfs` step), so that it auto-regenerates only when needed (any tour trace/segments/Fiche changes, or new zone added).
9. As a referent, I want the global map regeneration decision to appear in the `[perf]` report with its own subject line, so that I can verify what the pipeline did.
10. As a developer, I want the global map state (fingerprint) stored in the versioned generation state (`generation-state.json`), so that incremental logic works correctly across runs.
11. As a volunteer, I want a link in the home page Menu to access the global map (`/tours`), so that I can easily find it from the main entry point.
12. As a developer/referent, I want a link in the home page Menu to access `/admin/import-parcours` **only in development mode**, so that I can import new GPX traces during development without exposing it in production.
13. As a volunteer, I want the global map page (`/tours`) to have a Menu drawer with a download link for the global PDF (`Carte_tous_les_parcours.pdf`), just like zone map pages have for their zone PDFs, so that I can download the global map for offline use or printing.

## Implementation Decisions

### 1. New Route `/tours`
- Static Next.js App Router route at `app/tours/page.tsx` (no dynamic params)
- Server component that renders a client component `GlobalToursMap`
- No `generateStaticParams` needed (single static route)
- Metadata title via existing `pageTitle('/tours')` from `lib/route-meta.ts`

### 2. Menu Links on Home Page
- Modify the Menu drawer component (likely `components/menu-drawer.tsx` or similar in `app/layout.tsx`) to add two links in a new "Outils" or "Développement" section:
  - **"Voir tous les parcours"** → `/tours` (always visible)
  - **"Importer des parcours"** → `/admin/import-parcours` (only rendered when `process.env.NODE_ENV === 'development'`)
- The dev-only link uses a client-side check or a server component that conditionally renders based on `process.env.NODE_ENV` (Next.js replaces this at build time, so prod builds won't include the link at all)
- Links styled consistently with existing Menu items (shadcn/ui `Button` as link pattern or `Link` with button styling)

### 3. Menu Drawer on Global Map Page (`/tours`)
- The `/tours` page should show the same Menu drawer as zone map pages (`/tours/[zoneId]/[type]`)
- Update `headerFlags` in `lib/route-meta.ts` to return `menu: 'tours'` for pathname `/tours` (currently only matches `/tours/`)
- Update `menuLinks` in `lib/menu-links.ts` to return a link for the global PDF when pathname is `/tours`:
  - Kind: `'pdf-carte'`
  - Href: `/pdf/Carte_tous_les_parcours.pdf`
  - Label: `'Télécharger le PDF de la carte'` (same as zone maps)
- The existing `MenuLinks` component and `MenuDrawer` will render it automatically

### 4. Global Map Component (`components/global-tours-map.tsx`)
- Client component (`'use client'`) using existing Leaflet infrastructure
- Reuses: `loadTourRouteGeoJson`, `drawGeoJsonRoute`, `addLabelMarker`, `addStartEndMarkers`, `getLineCoordinates`, `LeafletMap`
- Builds a flat list of all tours from all zones, with their **zone-local index** for color assignment:
  - For each zone: bike tours first (in generation order), then walking tours
  - Color = `TOUR_COLORS[zoneLocalIndex % TOUR_COLORS.length]`
  - Same palette as zone maps (`components/tours-map.tsx`) — kept verbatim for parity
- Draws all tours on one map, fits bounds to all traces
- Same marker/label style as zone maps (small start/end markers, label at mid-point with tour name in track color)

### 5. Global PDF Generation (`scripts/generate-pdfs.ts`)
- New function `generateGlobalMapPdf(allTours: TourDistances[], logo)` 
- Landscape PDF like zone maps, full-page map panel
- Uses same `MAP_COLORS` palette (RGB triplets) and same rendering logic (`planView`, `buildMapBackground`, `projectToPanel`, `renderMapPanel` adapted)
- Tours drawn in the same order as the web map: all zones, each zone bike then walking, zone-local index for color
- Includes: VRNB logo, title "Toutes les zones - Tous les parcours", contact info, legend (green=Départ, blue=Parcours, red=Arrivée), OSM attribution
- Saved to `public/pdf/Carte_tous_les_parcours.pdf` (root of pdf folder, not in a zone subfolder)
- Helper `globalMapPdfPath(rootDir)` in `generation-helpers.ts`

### 6. Generation State (`scripts/generation-state.ts`)
- Add `globalMap: string | undefined` field to `GenerationState` interface
- Add `GlobalMapStateUpdate` interface for pipeline updates
- Extend `nextGenerationState` to accept optional `globalMapUpdate` and merge it
- Add `withMissingGlobalMapFingerprint` to backfill fingerprint for existing global map on fresh clones
- Update `readGenerationState` to parse `globalMap` from JSON
- Re-export `globalMapKey` from `generation-helpers.ts` (returns `'global'`)

### 7. Generation Plan (`scripts/generation-plan.ts`)
- New `GlobalReason` type: `forced | parcours-changed | missing-global-map | no-global-map-state | global-map-changed | up-to-date`
- New `GlobalDecision` interface: `{ regenerateGlobalMap: boolean; reason: GlobalReason }`
- Extend `GenerationPlan` to include `globalDecision: GlobalDecision`
- Decision logic in `planGeneration`:
  - `forced` → regenerate
  - No state / version changed → regenerate (but version change already handled at Parcours level; global map depends on Parcours decisions)
  - Any Parcours in the run has `rerouteSegments` or `regenerateFiche` true → `parcours-changed` → regenerate
  - Global map missing on disk → `missing-global-map` → regenerate
  - No fingerprint in state → `no-global-map-state` → regenerate
  - Fingerprint on disk differs from state → `global-map-changed` → regenerate
  - Else → `up-to-date`
- The global map is considered part of **every run** (not filterable by `--tour`/`--zone`): if any selected tour changes, the global map regenerates. A run with filters still regenerates the global map if the filtered tours changed.

### 8. Generation Subjects (`scripts/generation-subjects.ts`)
- New `GLOBAL_MAP_SUBJECT: PerfSubject` with:
  - `id: 'carte globale'`
  - `label: 'Carte globale'`
  - `plural: 'cartes globales'`
  - `unit: { singular: 'carte', plural: 'cartes' }`
  - `changed: { singular: 'regénérée', plural: 'regénérées' }`
  - `unchanged: { singular: 'ignorée', plural: 'ignorées' }`

### 9. Generation Helpers (`scripts/generation-helpers.ts`)
- Add `globalMapPdfPath(rootDir: string): string` → `join(pdfRootDir(rootDir), 'Carte_tous_les_parcours.pdf')`
- Add `globalMapKey(): string` → `'global'`

### 10. Pipeline Integration (`scripts/generate-pdfs.ts`)
- In `main()`:
  - Compute `globalMapFingerprint = fingerprintDocument(globalMapPdfPath(rootDir))` before plan
  - Pass to `planGeneration` via extended input (add `globalMapFingerprint` field)
  - After rendering Fiches and zone maps, if `runPlan.globalDecision.regenerateGlobalMap`:
    - Call `generateGlobalMapPdf(allTours, logo)` (allTours = all vTours + pTours, not filtered)
    - Track `renderedGlobalMap = true`
  - In state updates: create `GlobalMapStateUpdate` with fingerprint if rendered
  - In `reportRun`: include `GLOBAL_MAP_SUBJECT` in subjects, add global map counters

### 11. Generation Steps (`scripts/generation-steps.ts`)
- No changes needed: `generate-pdfs.ts` is already the last step and runs unconditionally

## Testing Decisions

### Unit Tests (Vitest)
- **`generation-plan.spec.ts`**: Test `GlobalDecision` logic with fake inputs
  - Forced run → regenerate
  - Any Parcours changed → regenerate
  - Global map missing on disk → regenerate
  - No state entry → regenerate
  - Fingerprint mismatch → regenerate
  - All up to date → no regenerate
- **`generation-state.spec.ts`**: Test `globalMap` field read/write/merge/backfill
- **`generation-helpers.spec.ts`**: Test `globalMapPdfPath`, `globalMapKey`

### Integration Tests
- **`generate-pdfs.spec.ts`** (or similar): Run `generate-pdfs.ts` on a fixture tree, verify global PDF created at correct path with expected content (or at least file exists and is non-empty)
- **`generation-steps.spec.ts`**: Verify orchestrated run includes global map in `[perf]` report

### E2E Tests (Playwright)
- **`e2e/global-tours-map.spec.ts`**:
  - Visit `/tours` → map loads, all tours visible, colors match zone maps (spot-check V1 and V200 both red)
  - Start/end markers and labels present
  - Map fits all tours
  - Menu drawer opens and shows "Télécharger le PDF de la carte" link pointing to `/pdf/Carte_tous_les_parcours.pdf`
  - Clicking the link downloads the global PDF

### Prior Art
- Zone map component: `components/tours-map.tsx` (web), `generateZoneMapPdf` in `generate-pdfs.ts` (PDF)
- Zone map tests: `e2e/tours-map.spec.ts`, `generate-pdfs` tests in `scripts/*.spec.ts`
- Generation plan tests: `scripts/generation-plan.spec.ts` (pure function with fake inputs)
- Generation state tests: `scripts/generation-state.spec.ts`

## Out of Scope

- Adding the global PDF to zone packs
- Filtering the global map by practice type (V/P toggle) — shows both together
- Separate global maps per practice type
- Clustering or decluttering for overlapping tours (map shows all at once)
- Mobile-specific layout changes beyond existing responsive behavior
- Analytics/tracking for the new route

## Further Notes

- The color duplication (V1 and V200 both red) is **intentional** per user requirement: "couleurs identiques à celle dans la zone". This matches the zone map visual language.
- The global map is **not filterable** by `--tour`/`--zone` in the pipeline: it always represents the full catalogue. A filtered run that changes some tours will still regenerate the global map.
- The global PDF uses the same high-resolution tile rendering (`MAX_VIEW_PIXELS = 3072` like zone maps) for print quality.
- The `GENERATION_STATE_VERSION` does **not** need to be bumped: the new `globalMap` field is optional in the JSON (undefined when missing), and `withMissingGlobalMapFingerprint` backfills it on fresh clones.
- The global map route `/tours` does not conflict with existing `/tours/[zoneId]/[type]` because Next.js matches static routes first.
- The dev-only admin link uses `process.env.NODE_ENV === 'development'` which Next.js evaluates at build time: the link is completely stripped from production bundles (no runtime check needed).
